# AI 面板交互基础设施 v0.7 — 设计文档

> **版本**：v0.7-draft  
> **基线**：v0.6（slash command + 双链 + 对话历史）  
> **日期**：2026-07-30  

---

## 一、问题

当前 AI 面板（FsAiPanel）缺少基本的消息操作能力：

| 缺失能力 | 后果 |
|----------|------|
| 不能编辑已发送的消息 | 打错字只能追加"纠正一下" |
| 不能重试 AI 回复 | AI 跑偏了只能重新打字 |
| 不能删除消息 | 错误的对话只能通过刷新清除 |
| 不能复制 AI 输出 | 好内容要手动选中复制 |
| 任务卡片不能展开/收起 | 长回答占据整个面板 |

目标：给 AI 面板加上基本的消息操作，让交互体验接近 ChatGPT/Claude Code。

---

## 一.5 行业参考：ChatGPT 消息交互设计（2025-2026）

来源：OpenAI Developer Community / Reddit / CHI 2026 论文

### 编辑消息

ChatGPT **曾经**支持编辑任意历史消息。2025 年初的静默更新将编辑能力限制为**仅最后一条消息**，引发大规模用户抗议。用户将编辑功能称为"整个对话的方向盘"——修改早期消息可以调整 AI 对后续内容的理解，这是多轮对话的核心交互。

**织梦机的结论：编辑应该支持任意历史消息，不能只限最后一条。**

### 重试（重新生成）

ChatGPT 旧版在重试后会保留前一个版本，用户可以通过 ← → 箭头在版本间切换。更新后重试直接覆盖旧回答，用户无法对比不同版本或恢复有用内容。

**织梦机的结论：重试应保留版本历史，支持版本切换。**

### 删除消息

ChatGPT 目前只支持删除整个对话，不支持删除单条消息。用户需要这个能力来清理错误/测试消息。

### 草稿自动保存

ChatGPT Desktop 在切换模式时会清空输入框中的未发送草稿，用户损失大量内容。社区要求 autosave + 草稿恢复。

**织梦机的结论：AI 面板的输入框草稿已在 localStorage 中保存（当前已实现）。**

### 错误状态

ChatGPT 使用同一红色样式处理不同类型的错误（流中断、网络错误、系统错误、频率限制），用户无法区分哪些可重试、哪些不可恢复。

### 长对话导航

用户在长对话中难以定位之前的消息。社区建议：侧边栏问题大纲、消息高亮区分、折叠机制。

## 二、设计

### 2.1 消息列表（现有）

当前每个任务卡片的结构：

```
┌─────────────────────────────────────┐
│ 用户输入（一段文本）                 │
│ 状态行（阶段 + 状态点）              │
│ 操作摘要（回答/创建/修改）           │
│ AI 回答（markdown 渲染）             │
│ 证据展开（实际依据 N 项）            │
│ 草稿展开（未提交草稿）               │
│ 提交结果（文件创建/修改）            │
│ ─────────────                       │
│ [撤回] 按钮（仅写入任务）            │
└─────────────────────────────────────┘
```

### 2.2 新增操作

#### 操作 1：复制回答

```
场景：AI 的回答写得好，想粘贴到正文
交互：鼠标悬停在 AI 回答上 → 显示 [复制] 图标 → 点击复制 → 短暂显示"已复制"
```

轻量操作，不需要额外状态管理。

#### 操作 2：重新生成（带版本历史）

```
场景：AI 回答不符合预期
交互：鼠标悬停 → [重新生成] → AI 重新回答
      旧版本保留，可通过 ← → 箭头切换查看
行为：
  1. 用同样的 userInput 重新调 AI
  2. 旧版本不删除，存入 versions[]
  3. 可通过箭头切换查看不同版本
  4. 当前版本有视觉指示器（圆点指示第 N/总版本）
```

参考 ChatGPT 旧版设计（2025 年初被移除，用户强烈抗议）。版本历史让重试变得可逆，不是毁灭性操作。

**数据结构变动：**

```typescript
interface ProjectAiTaskCard {
  // ... 现有字段
  versions?: { answer: string; commit: AiFileActionCommit | null; draft: string | null; createdAt: number }[];
  currentVersion?: number;
}
```

#### 操作 3：编辑任意历史消息

```
场景：用户打错字、想换问法、或修改早期指令影响 AI 后续理解
交互：鼠标悬停在用户消息上 → [编辑] → 变为文本框 → 修改后保存
行为：
  1. 编辑任意历史消息（不限最后一条）
  2. 保存后，该条及之后的所有消息被标记为"已失效"
  3. AI 重新生成当前消息的回答
  4. 用户可继续对话
  5. 按 Esc 取消编辑
```

**关键设计决策：编辑后后续消息的处理**

| 方案 | 做法 | 复杂度 |
|------|------|--------|
| A) 截断 | 删除该条之后的所有消息 | 低 |
| B) 标记失效 | 后续消息标记为"此前的上下文已变化"，保留但灰显 | 中 |
| C) 完全重算 | 保留后续消息，让 AI 带着新上下文重新理解 | 高 |

**推荐：方案 B** — 标记失效而非截断。用户早期消息变了但后续 AI 回答仍有参考价值。标记为灰色让用户知道上下文已变，但不丢失信息。

#### 操作 4：删除单条消息

```
场景：错误消息、测试内容、或不想保留的对话
交互：鼠标悬停 → [删除] → 从列表移除
行为：
  1. 从 tasks 中移除该条
  2. 保存到 localStorage
  3. 不影响已写入硬盘的文件
```

#### 操作 5：收起/展开

```
场景：长回答占据大量空间
行为：最近 3 条默认展开，更早的历史任务默认折叠
      点击任务头部切换折叠状态
```

## 三、UI 变化

### 设计原则

- **复用现有 token**（`--accent`/`--text-muted`/`--border-default` 等），不引入新色调
- **Lucide 图标**，与已有按钮风格一致（如 `fs-ai-revert-btn` 的 `RotateCcw`）
- **hover 显示、键盘可达**：鼠标悬停 OR 键盘 Tab 聚焦到任务卡片时显示操作栏
- **操作按钮最小 44×44px hit area**（视觉图标可以 14-16px，但通过 padding 扩展点触区域）
- **渐变出现**：工具栏 `opacity 0→1 150ms ease`，不突然闪现

### 3.1 任务卡片新布局

```
┌─────────────────────────────────────┐
│ 用户消息                          [✏️ 编辑] [🗑 删除] │  ← hover/focus 显示
├──────────────────────────────────────┤
│ AI 回答（markdown 渲染）           [📋 复制] │  ← hover/focus 显示
│                                       │
│ 证据展开 / 提交结果 / 撤回按钮       │
│ ──────────────────────────────────── │
│ [🔄 重新生成]  ← 带 loading spinner     │  ← Phase 2
│ 版本 · ○ ○ ● ○ · ← →                │  ← Phase 2
└─────────────────────────────────────┘
```

### 3.2 编辑模式

```
┌─────────────────────────────────────┐
│ ┌──────────────────────────────┐    │
│ │ 编辑后的消息（预填原文）     │    │
│ └──────────────────────────────┘    │
│ [保存] [取消]  (Esc 取消)           │
└─────────────────────────────────────┘
```

### 3.3 交互行为对照（UX 规则覆盖）

| 操作 | 触发 | 反馈 | 键盘支持 | UX 规则 |
|------|------|------|----------|---------|
| 复制 | hover 显示 → 点击 | "已复制" toast 1500ms | Tab + Enter | §8 success-feedback |
| 删除 | hover 显示 → 点击 | "消息已删除 [撤销]" toast 4000ms | Tab + Enter | §8 undo-support |
| 重试 (Ph2) | 始终可见 | 按钮 → spinner + disabled | Tab + Enter | §8 loading-buttons |
| 编辑 (Ph3) | hover 显示 → 点击 | 消息变文本框 | Tab + Enter | §8 input-labels |
| 收起/展开 | 点击头部 | 内容折叠/展开，图标旋转 90° | Tab + Enter + Space | §7 state-transition |

### 3.4 样式规格

**操作栏（hover toolbar）：**
- 容器：`display: flex`, `gap: 4px`, `opacity: 0`, transition `150ms ease`
- 显示态：task-card 的 `:hover` 或 `:focus-within` 时 `opacity: 1`
- 按钮：`background: transparent`, `border: none`, `color: var(--text-muted)` → hover `var(--text-secondary)`
- 删除按钮：hover 时 `color: #d98d8d`（复用现有错误色）
- 点触区域：`padding: 10px` 确保 44×44px 最小点击区域（视觉图标 ~16px）
- Lucide icons：`size={14}` 或 `size={15}`，与现有按钮一致

**toast 反馈：**
- 复用现有 `useToast` 机制（App.tsx 已有 `showToast`）
- 复制成功：`showToast('已复制', 'success')`
- 删除撤销：`showToast('消息已删除', 'info')` + 行内撤销按钮

## 五、否决方向

- ❌ 不做消息分页加载（当前最多保留 50 条对话，已够用）
- ❌ 不做类似 ChatGPT 的对话分支管理
- ❌ 编辑消息不保留历史版本（编辑即替换）
- ❌ 不做右键菜单（全部用可见按钮）

# 织梦机 Gate A 返工报告

> 日期：2026-07-23  
> 对应 PRD：`docs/product/zhimengji-prd-v0.4.1.md`  
> 状态：返工源码交付；等待真实 Windows 构建与运行验收

## 一、返工裁定

第一次 Gate A 原型被拒绝。它把新产品做成旧数据库工作区旁边的 FS 模式，并同时引入有损 Markdown 往返、重复自动保存、错误的外部变化覆盖、伪会话恢复和未成立的 AI 面板。

本次返工按一条纵向主链重新实现：

```text
创建或打开任意本地作品目录
→ 显示真实文件树
→ 打开一份 Markdown / TXT
→ 编辑同一真实文件
→ 单一自动保存器执行版本校验写入
→ 外部变化时安全重载或进入冲突
→ 关闭重开恢复文件、光标和滚动位置
```

Gate B AI 没有进入当前主工作区。

## 二、主要变化

### 1. 单一产品工作区

- `App.tsx` 移除 `isFsMode` 与两套工作区分支。
- 启动页只保留两条真实入口：在织梦机开始创作、导入已有创作。
- 两条入口进入同一个本地项目工作区。
- 旧 SQLite 项目只作为一次性迁移来源出现。

### 2. 任意目录可接入

- `open_fs_project` 可以打开任意现有目录。
- 织梦机只新增隔离的 `.glyph` 辅助目录，不重组用户文件。
- 损坏的 `project.json` 会备份后重建，不阻止打开正文。
- `.glyph` / `.glyph-trash` 若为符号链接或异常文件会被拒绝，避免辅助数据逃出项目根目录。

### 3. 最小新建项目

- 新建作品只创建 `.glyph` 和 `正文.md`。
- 不再强制生成 `chapters / characters / world / notes` 英文骨架。
- 使用系统目录选择器选择父目录。

### 4. 真实 Markdown 编辑

- `FsDocumentView` 改为单一受控 Markdown 文本编辑器。
- 删除 Tiptap HTML → 正则 Markdown 的有损转换。
- 当前阶段优先保证原文不被编辑器私自重写。

### 5. 单一保存责任

- 只有 `App.tsx` 的 1.5 秒去抖负责自动保存。
- Store 使用内容版本进行检查写入。
- 保存期间继续输入时，旧保存完成不会把新内容误标成已保存。
- Tauri watcher 自身保存事件通过磁盘版本判断为无变化，不使用定时忽略窗口吞掉真实外部编辑。

### 6. 外部冲突与恢复

- 干净文件的外部修改自动重载。
- 本地有未保存内容时进入 `conflict`，自动保存暂停。
- 用户可以使用外部版本、本地草稿另存后重载、明确覆盖外部版本。
- 原文件消失时保留编辑缓存，可保存恢复副本。
- 使用外部版本会再次明确确认，避免误丢本地草稿。

### 7. 会话恢复

- 删除伪 `XMLHttpRequest` 保存逻辑。
- 使用 Tauri `save_session_state` 持久化当前文件、光标与滚动位置。
- 会话文件缺失或损坏不会阻止打开项目。

### 8. 文件提交与路径安全

- 所有相对路径拒绝绝对路径、盘符、`..` 与 Windows 反斜杠逃逸。
- 非现存嵌套路径通过最近现存祖先做项目边界校验。
- Windows 覆盖使用 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`。
- 临时文件使用同目录随机唯一名称。
- 新建文件采用 no-clobber，不覆盖并发出现的文件。
- 删除文件移动到 `.glyph-trash`，命名包含时间与 UUID。

### 9. 旧项目迁移

- 迁移目标必须不存在或为空。
- 写入失败会清理本次迁移产物。
- 中文长文件名按字符截断，避免 UTF-8 字节切片崩溃。
- 同名对象使用短 ID 避免互相覆盖。

## 五、发布阻断项

任何一项出现都不得冻结：

- 已有 Markdown 被编辑器重写或丢失；
- 保存失败后原文件损坏；
- 外部修改被自动覆盖；
- 自身保存持续触发冲突或重载循环；
- 关闭应用时未保存内容静默丢失；
- 普通目录无法接入；
- `.glyph` 删除后用户原作品无法继续由其他编辑器使用；
- 项目外路径可以通过正斜杠、反斜杠或符号链接访问。

# Glyph v0.1 稳定基线 — 技术规格说明

## 背景（Why）

**谁受影响：**
- Glyph 用户（编辑器体验不稳定）
- 开发迭代者（测试基础设施损坏、文档错位）

**当前行为：**
- 编辑器体验修复已完成代码量约 80%，但 10 个文件仍为 dirty 状态未提交
- vitest 配置路径过期：`include` 指向 `__tests__/` 和 `acceptance/`，实际测试文件在 `tests/unit/`
- acceptance 脚本扫描路径指向 `src/` 前缀（如 `src/features/`），但项目使用 flat 结构（`features/`），实际上扫了 0 个文件
- CLAUDE.md 目录结构描述与当前真实结构不一致
- tauri-driver E2E 测试流程有初步探针脚本（4 个脚本，~800 行）但未形成可稳定运行的测试流程
- 数据库运行产物（glyph-api.db\*）之前未 gitignored

**目标行为：**
- 所有 dirty 修改经验证后提交
- vitest 可通过并跑绿所有单元测试
- acceptance 脚本路径修正后可扫描真实文件
- CLAUDE.md 描述与真实目录一致
- tauri-driver E2E 基本流程可运行
- 数据库产物不再意外出现在工作区

**为什么现在做：**
- 体验翻新已完成大半，代码不提交会一直 dirty，增加后续混淆
- 测试基础设施损坏（vitest 路径、acceptance 路径）导致任何"跑测试验证"步骤都不可信
- 目录整理刚完成，不顺势修复路径依赖会留下技术债
- 后续迭代（v0.2 AI 对话等）需要可靠的测试基线

**怎么算做完（验收条件）：**
1. ✅ vitest 配置修正，`npm test` 可运行并通过已有单元测试
2. ✅ 10 个 dirty 修改经验证后提交（含体验翻新 + 目录整理重命名）
3. ✅ acceptance 脚本路径修正，`npm run accept` 可运行扫描真实文件
4. ✅ CLAUDE.md 目录列表更新为当前真实结构
5. ✅ tauri-driver E2E 基本探测流程可运行（至少 `td-probe.mjs` 可连接并反馈）
6. ✅ `glyph-api.db*` 已 gitignored 不会再出现

## 技术方案（必填）

### M1：修复 vitest 配置

**文件：** `vitest.config.ts`

```diff
- include: ['src/**/*.test.{ts,tsx}', '__tests__/**/*.test.{ts,tsx}'],
- exclude: ['**/node_modules/**', '**/*.spec.ts', 'acceptance/**'],
+ include: ['src/**/*.test.{ts,tsx}', 'tests/unit/**/*.test.{ts,tsx}'],
+ exclude: ['**/node_modules/**', '**/*.spec.ts', 'tests/acceptance/**'],
```

改动后执行 `npm test` 验证。

### M2：验收并提交 dirty 修改

**待验收文件分类：**

真实内容修改（体验翻新）：
| 文件 | 关键变更 | 验证方式 |
|------|---------|---------|
| App.tsx | 移除 showOutline，专注模式图标换 | `npm run build` |
| components/Bookshelf.tsx | 自定义封面渐变 | `npm run build` |
| components/DocOutline.tsx | 拖拽逻辑重写 | `npm run build` |
| components/DocumentView.tsx | 编辑器点击修复 | `npm run build` |
| styles/global.css | user-select 重构，拖拽样式 | `npm run build` |
| api.rs | 路由 `{id}`→`:id`，API 独立线程 | `cargo check` |
| lib.rs, main.rs | `--api-only` 模式 | `cargo check` |
| package.json | 依赖变更 | `npm install` |
| package-lock.json | lockfile 同步 | 随 package.json |

纯粹重命名（目录整理，在 staged 中）：
- `docs/*` 下全部文件——仅路径变更，内容不变
- `tests/*` 下全部文件——仅路径变更，内容不变
- `src-tauri/*` 下全部文件——仅路径变更 + Cargo.toml 2 行路径修改
- `lib/mock-helper.ts`——路径变更

**提交策略：**
- **Commit 1:** `chore: v0.1 experience polish — editor UX, IME, focus mode, API-only mode`
- **Commit 2:** `chore: restructure project root — consolidate docs, tests, src-tauri`（如果用户希望分开提交清理和功能改动的化）

或者合并为一个提交。

## 测试计划

### 测试范围

| 测试类型 | 覆盖 | 命令 |
|---------|------|------|
| TypeScript 编译 | 全部 TS 源码 | `npx tsc --noEmit` |
| Rust 编译 | 全部 Rust 源码 | `cargo check` |
| 单元测试 | vitest unit tests | `npm test` |
| Acceptance 静态检查 | 代码风格/安全 | `npm run accept:static` |
| Acceptance 样式合规 | CSS 规范 | `npm run accept:css` |
| Acceptance 契约链 | 接口完整性 | `npm run accept:contracts` |
| Vite 构建 | 前端打包 | `npm run build` |
| tauri-driver 探测 | 基础连接 | `node tests/e2e/td-test.mjs` |

### 测试策略

1. 先修路径 → 再跑测试 → 改到通过为止
2. acceptance 脚本可能大部分是 false-positive 通过（扫 0 个文件），修正后预期会扫描实际文件并可能需要修复问题
3. tauri-driver 探测为独立验证步骤，不影响其他模块

### 回归风险

- acceptance 脚本路径修正后可能暴露出之前被 mask 的违反项（低风险，属于正常修复）
- 目录整理已通过 `cargo check` 验证 Rust 编译正常

## 风险与回滚

### 已知风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| acceptance 脚本修正后暴露出真正的问题 | 中 | 低 | 修复暴露的问题，或放宽检查条件 |
| tauri-driver 探测因环境问题不可运行 | 中 | 中 | 先确认环境是否满足（WebView2, tauri-driver 安装），不阻塞其他模块 |
| 某 dirty 修改在验证时发现遗漏 | 低 | 低 | 补修即可 |

### 回滚方案

不适用——本版本不涉及数据迁移、不可逆操作或外部服务变更。所有修改均为代码更改 + 文件移动。如有问题，`git reset HEAD~1` 即可回滚。

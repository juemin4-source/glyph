# AI 稳定性基线

这份源码用于后续逐步加固 AI 功能。当前版本只处理阻断主链的问题，没有新增产品功能。

## 本次修复

- 正式 AI 请求使用 AI Control Center 中实际选中供应商的 `endpoint` 与 `timeoutMs`。
- 将 base URL 规范化为真实的聊天补全地址，避免请求错误地固定到 `localhost:3001`。
- Tauri 调用参数统一为 camelCase。
- Rust 非流式客户端增加 Anthropic 请求头、system prompt 与响应格式兼容。
- 修复建议和写入预览成功后错误读取 `response.content` 的问题。
- 删除由上述异常触发的隐式二次模型调用。
- AI 生成期间锁定输入和发送按钮，避免重复提交。
- 增加“停止”按钮，并将取消信号贯穿通用、章节包和正文生成路径。
- 前端请求真正应用供应商超时配置。
- AI 上下文快照限制为 48,000 字符，防止项目增长后无限膨胀。
- 恢复标准 `src/` 目录并补齐 Vitest 的 jsdom/IndexedDB 测试环境，避免把 Playwright 用例误当作单元测试执行。

## 刻意保留的范围

- 当前主链仍以非流式 Tauri 请求为主；真正的逐 token 流式输出建议作为下一阶段单独实现。
- 上下文目前采用硬上限止血，尚未实现按当前章节、角色关联和检索相关性进行选择。
- 项目中仍有旧 BYOK/API 兼容层，本轮不做大规模删除，以降低回归风险。

## 建议下一步

1. 为一次 AI 操作建立统一 `requestId`，贯穿 UI、Router、Rust 和日志。
2. 用 Tauri event 或 channel 实现真正的流式输出。
3. 将上下文构建改为“当前对象 + 上游摘要 + 关联实体”，并显示 token 预算。
4. 为重复提交、取消、超时、错误 endpoint 和大项目上下文增加自动化测试。
